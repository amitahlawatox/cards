# Bespoke Card Studio Global Event Coverage Matrix

## Purpose

This document turns the regional expansion request into a concrete coverage inventory for:

- United States
- Canada
- United Kingdom
- Europe
- Australia
- New Zealand
- India

It is based on official or government-backed holiday calendars where possible, then translated into invitation-search coverage needs.

## Source Baseline

Primary sources used:

- US federal and state/cultural holiday overview: `usa.gov/holidays`
- Canada public holidays: `canada.ca/.../public-holidays.html`
- UK bank holidays: `gov.uk/bank-holidays`
- Australia public holidays: `fairwork.gov.au/employment-conditions/public-holidays`
- New Zealand public holidays: `employment.govt.nz/.../public-holidays-and-anniversary-dates`
- India central and state holiday calendars: `india.gov.in/calendar`
- Europe public holiday overview by country: `eures.europa.eu/.../public-holidays-overview_en`

## Status Definitions

- `Covered`: the site already has a clear occasion or seasonal cluster that maps to this intent
- `Partial`: some relevant coverage exists, but the event needs its own hub or supporting pages
- `Missing`: no meaningful dedicated cluster exists yet

## Implementation Rule

For each approved event cluster, build:

- `main hub page`
- `modifier pages`
- `template collection page`
- `wording page`
- `seasonal or regional hub support`
- internal links from existing indexed pages

## Immediate Decision

The current best-interest move is **not** to hand-build hundreds of event pages at once.

The correct move is:

1. maintain this region-by-region inventory
2. add the missing global high-priority clusters first
3. expand country- and community-specific pages in controlled waves
4. keep checking Search Console so new pages do not become indexing debt
